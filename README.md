# «Чи Ви Знали?» — автоматичний конвеєр Reels

Railway-застосунок бере готові ZIP-архіви з Google Drive за рядками Google
Sheet, монтує вертикальні відео, показує їх у Telegram Mini App та автоматично
публікує Reels на Facebook-сторінку й у пов'язаний Instagram-акаунт.

## Поточний розклад

Усе працює за часовим поясом `Europe/Kyiv`, включно з переходом на зимовий
і літній час:

1. Вранці та ввечері ChatGPT-автоматизація створює сценарій, JPG та ZIP,
   завантажує ZIP на Drive і ставить рядку Google Sheet статус `DONE`.
2. Railway часто перевіряє чергу у вікнах **07:45–10:30** і
   **15:45–18:30**. Коли знаходить готовий ZIP — монтує MP4, завантажує його
   у Drive та надсилає сповіщення в Telegram.
3. Застосунок публікує готовий MP4 як Reel із запасом часу на ручні правки:
   - о **10:00** — матеріал, згенерований попереднього вечора;
   - о **18:00** — матеріал, згенерований поточного ранку;
   - на Facebook Page;
   - в Instagram professional account.
4. Якщо потрібне відео ще не готове рівно о 10:00/18:00, застосунок чекає
   його у двогодинному вікні та перевіряє щохвилини. Відео з іншого
   генераційного слота замість нього не публікується.
5. TikTok і YouTube залишаються ручними.

Після автопублікації Google Sheet **не змінюється**. Статус `DONE → PUBLISHED`
і дата записуються лише після ручного натискання **«Опубліковано»** у Mini App.

## Захист від повторної публікації

Слот, Facebook post ID та Instagram media ID зберігаються в `appProperties`
MP4 на Google Drive. Під час перегенерації ці мітки переносяться в маленький
marker-файл, тому заміна відео теж не створить повторний Reel. Якщо одна
платформа успішна, а друга тимчасово впала, застосунок повторює лише невдалу
через 5 хвилин. Таблиця для цієї технічної інформації не використовується.

## Telegram Mini App

Інтерфейс лишається ручним центром контролю:

- прев'ю та завантаження MP4;
- копіювання назви й опису з таблиці;
- **«Перегенерувати»** — видаляє MP4 і запускає повторний монтаж;
- **«Опубліковано»** — єдина дія, що ставить у таблиці `PUBLISHED` і дату.

## Змінні Railway

Основні чинні змінні Google/Telegram лишаються без змін. Для Meta потрібні:

| Змінна | Значення |
|---|---|
| `ENABLE_WEB` | `1` |
| `PUBLIC_URL` | публічний HTTPS URL Railway без `/` у кінці |
| `ENABLE_FB` | `1` після перевірки доступу |
| `ENABLE_IG` | `1` після перевірки доступу |
| `META_PAGE_ID` | ID Facebook-сторінки |
| `META_IG_USER_ID` | ID пов'язаного Instagram professional account |
| `META_PAGE_ACCESS_TOKEN` | довготривалий Page access token |
| `META_GRAPH_VERSION` | необов'язково; за замовчуванням `v25.0` |

Не комітьте access token і не надсилайте його в чат. Додавайте його лише як
Railway Variable. Повна одноразова інструкція: [docs/META_SETUP_UK.md](docs/META_SETUP_UK.md).

## Перевірка

```bash
npm ci
npm test
```

`GET /healthz` показує, чи ввімкнені та заповнені Meta-змінні, але ніколи не
повертає токен.

## Основні файли

```text
web/server.js          HTTP-сервер, Mini App, запуск фонових процесів
web/public/index.html  прев'ю та ручні кнопки
src/monitor.js         пошук DONE, завантаження ZIP, монтаж і Drive
src/autopublish.js     слоти 10:00/18:00, retry і дедуплікація
src/meta.js            Instagram/Facebook Reels через Graph API
src/publish.js         спільний маршрутизатор платформ
src/videos.js          MP4 та appProperties на Drive
src/sheets.js          читання черги й ручне DONE → PUBLISHED
test/                  тести Meta API, розкладу та захисту від дублів
```

Старі GitHub Actions у `.github/workflows` лишені лише для ручного запуску;
їхній cron вимкнено. Робочий процес постійно працює на Railway.
