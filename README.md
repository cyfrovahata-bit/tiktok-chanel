# Автоматичний конвеєр коротких відео

Railway-застосунок бере готові ZIP-архіви з Google Drive за рядками Google
Sheet, монтує вертикальні відео з озвучкою й субтитрами, показує їх у
Telegram Mini App, автоматично публікує на YouTube, TikTok та в Instagram і
веде відповіді на коментарі через схвалення в Telegram.

Один репозиторій обслуговує кілька каналів: код спільний, а таблиця, папки
Drive і токени — у кожного свої, окремим сервісом Railway.

**Карта проєкту з описом усіх модулів: [docs/MAP.md](docs/MAP.md).**

## Поточний розклад

Усе працює за часовим поясом `Europe/Kyiv`, включно з переходом на зимовий
і літній час:

1. ChatGPT за відкладеними завданнями створює сценарій, JPG та ZIP,
   завантажує ZIP на Drive і ставить рядку Google Sheet статус `DONE`.
2. Railway стежить за чергою і, побачивши готовий ZIP, монтує MP4,
   завантажує його у Drive та надсилає сповіщення в Telegram.
3. Публікація йде за розкладом, у кожної платформи свій
   (`AUTO_PUBLISH_HOURS_YOUTUBE`, `_TIKTOK`, `_INSTAGRAM`). Кожен слот живе
   дві години, щоб затримка монтажу не з'їдала пост.
4. Черга спільна на всі платформи: береться найстаріший ролик, якого бракує
   хоч комусь, і кожна публікує саме його у своє вікно. Наступний ролик
   рушає лише тоді, коли попередній отримали всі.
5. Facebook автоматично не публікується — замість цього приходить
   нагадування в Telegram (`ENABLE_FB_REMINDER=1`), одне на ролик.

Після автопублікації Google Sheet **не змінюється**. Статус `DONE → PUBLISHED`
і дата записуються лише після ручного натискання **«Опубліковано»** у Mini App.

## Захист від повторної публікації

ID постів усіх платформ і клейми вікон зберігаються в `appProperties`
MP4 на Google Drive. Під час перегенерації ці мітки переносяться в маленький
marker-файл, тому заміна відео теж не створить повторний Reel. Якщо одна
платформа успішна, а друга тимчасово впала, застосунок повторює лише невдалу
через 5 хвилин. Таблиця для цієї технічної інформації не використовується.

## Telegram Mini App

Інтерфейс лишається ручним центром контролю:

- прев'ю та завантаження MP4;
- копіювання назви й опису з таблиці;
- **«Перегенерувати»** — видаляє MP4 і запускає повторний монтаж;
- **«Опубліковано»** — єдина дія, що ставить у таблиці `PUBLISHED` і дату.

## Довга добірка

Кілька готових епізодів склеюються в одне довге відео (Mini App → «Довга
добірка», або `node scripts/compile-long.js --limit 15`). Добірка починається
вступом — «Чи знав ти таку Україну? 15 фактів, яких ти, можливо, не знав» — а
перед кожним сюжетом іде картка «ФАКТ 3» з голосом «Факт третій».

Епізоди йдуть **від найстарішого до найсвіжішого** — у мінідодатку список
навпаки (новіші зверху), але в добірці свіжий ролик стає останнім: інакше
відео відкривалося б тим, що глядач бачив позавчора.

Фоном вступу стає **прев'ю**: картинка, яку власник малює в ChatGPT промтом
[prompts/prevyu-dovhoho-video.txt](prompts/prevyu-dovhoho-video.txt) і
вивантажує кнопкою «Завантажити прев'ю» в мінідодатку. Вона лежить на Drive
під сталим іменем `compilation-preview.jpg`, тож працює й наступного тижня,
доки її не замінять. Немає прев'ю — вступ лишається на чорному тлі. Ці репліки складають
**голосовий банк** у `assets/voice`: кожна синтезується РАЗ і далі просто
підставляється, тож збірка не витрачає символів ElevenLabs.

Згенерувати банк наперед і закомітити (потрібен ключ TTS):

```bash
node scripts/build-voice-bank.js 20
git add assets/voice
```

Чого в теці немає — збірка шукає в папці Drive (`voice-<ключ>.mp3`), а якщо
немає й там, синтезує сама й одразу кладе на Drive. Подробиці:
[assets/voice/README.md](assets/voice/README.md).

## Змінні Railway

Основні чинні змінні Google/Telegram лишаються без змін. Для Meta потрібні:

| Змінна | Значення |
|---|---|
| `ENABLE_WEB` | `1` |
| `PUBLIC_URL` | публічний HTTPS URL Railway без `/` у кінці |
| `ENABLE_FB` | `1` після перевірки доступу |
| `ENABLE_IG` | `1` після перевірки доступу |
| `META_PAGE_ID` | ID Facebook-сторінки |
| `META_IG_USER_ID` | ID пов'язаного Instagram professional account |
| `META_PAGE_ACCESS_TOKEN` | довготривалий Page access token |
| `META_GRAPH_VERSION` | необов'язково; за замовчуванням `v25.0` |
| `VOICE_FOLDER_ID` | необов'язково; папка Drive для голосового банку (типово та сама, що й для відео) |
| `VOICE_BANK_DIR` | необов'язково; тека банку (типово `assets/voice`) |
| `PREVIEW_FOLDER_ID` | необов'язково; папка Drive для прев'ю добірки (типово та сама, що й для відео) |

Не комітьте access token і не надсилайте його в чат. Додавайте його лише як
Railway Variable. Повна одноразова інструкція: [docs/META_SETUP_UK.md](docs/META_SETUP_UK.md).

## Перевірка

```bash
npm ci
npm test
```

`GET /healthz` показує, чи ввімкнені та заповнені Meta-змінні, але ніколи не
повертає токен.

## Основні файли

```text
web/server.js          HTTP-сервер, Mini App, запуск фонових процесів
web/public/index.html  прев'ю та ручні кнопки
src/monitor.js         пошук DONE, завантаження ZIP, монтаж і Drive
src/autopublish.js     розклад платформ, спільна черга, retry і дедуплікація
src/meta.js            Instagram/Facebook Reels через Graph API
src/youtube.js         Shorts через YouTube Data API v3
src/tiktok.js          TikTok Content Posting API
src/comment-flow.js    відповіді на коментарі зі схваленням у Telegram
src/publish.js         спільний маршрутизатор платформ
src/videos.js          MP4 та appProperties на Drive
src/compile-long.js    довга добірка: вступ, оголошення фактів, склейка
src/voice-bank.js      разово синтезовані репліки вступу й «Факт перший»
src/preview.js         прев'ю добірки на Drive — фон вступної заставки
src/sheets.js          читання черги й ручне DONE → PUBLISHED
test/                  тести Meta API, розкладу та захисту від дублів
```

Робочий процес постійно працює на Railway. У `.github/workflows` лишилися
лише дві ручні дії — `regenerate.yml` (перескласти відео з наявних кадрів) і
`sample.yml` (демо-ролик); cron у них вимкнено. Старий конвеєр генерації тем
на GitHub Actions прибрано.

## Пам’ять коментарів Facebook та Instagram

У `comments.json` на Drive зберігаються окремі гілки за платформою, ID
допису та ID верхнього коментаря. Репліки зливаються за ID, з датами,
авторами й ознакою відповіді каналу. Зберігаються також ручні відповіді,
побачені через Meta API, та відповіді, опубліковані через Telegram.
Відсутність старої репліки в новому пакеті API не стирає історію; видалені
в соцмережі репліки можуть лишатися у збереженій історії.

Коментарі й відповіді догортаються через курсори (до 20 додаткових сторінок
на список). Кожна відповідь отримує лише свою гілку. Для вже активної
гілки створюється одна кандидатура, без окремої відповіді на її початок.

Сюжет береться з актуального рядка Google Sheet (тексти слайдів у колонці G),
разом із назвою й описом. Надійний зв’язок із рядком запам’ятовується,
навіть якщо MP4 згодом видалено. Неоднозначний збіг не закріплюється;
без збігу модель отримує явне попередження про невідомий ролик.
YouTube не використовує цю нову пам’ять.

Назва, опис і сюжет Meta-допису кешуються в `comments.json` за
`платформа:ID допису` після першого надійного зіставлення. Наступні гілки
того самого допису використовують цю копію без читання таблиці або списку
MP4. Редагування сюжету в таблиці після кешування не оновлює цю копію.

## Початковий збір Meta-історії

`COMMENTS_HISTORY_ENABLED=1` вмикає одноразовий збір усіх доступних постів
Facebook та Instagram. За хвилину обробляється до п’яти постів кожної
платформи; курсори, лічильники й помилки зберігаються в `comments.json`.
Після перезапуску збір продовжується. При помилці пауза 15 хвилин.
Історичний збір не викликає OpenAI, не лайкає і не публікує відповіді.

Час старту є постійною межею: старі Meta-коментарі (і коментарі без дати)
не стають кандидатами на відповіді. Нові коментарі продовжують оброблятися
раз на 15 хвилин під час збору й після нього. Раз на добу обидві платформи
перевіряють старі дописи до `META_COMMENTS_DEEP_MAX` (типово 200).
Пам’ять містить лише доступні через API дані. Прогрес і кількість збережених
гілок/реплік показує захищений `/api/comments/state`.
